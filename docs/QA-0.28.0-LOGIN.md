# QA входа Horse Club OS 0.28.0

## Подготовка

- Устанавливать только после резервной копии и проверки рабочей версии 0.27.0.
- Подготовить отдельные тестовые учётные записи администратора и тренера Horse Club OS.
- Не использовать реальные пароли в скриншотах и отчётах.

## Сценарии

1. Выйти из WordPress и открыть корень домена CRM. Должна открыться фирменная форма Horse Club OS.
2. Ввести неверный пароль. Форма должна показать общее сообщение без указания, существует ли пользователь.
3. Войти администратором. Должна открыться главная панель Horse Club OS со всеми разрешёнными разделами и финансами.
4. Нажать «Выйти». Сессия должна завершиться, после чего снова открывается форма входа.
5. Войти тренером. Должна открыться та же рабочая панель, но без платежей, абонементов, отчётов и финансовых данных.
6. Проверить, что тренер не может открыть финансовые URL напрямую и не может удалять записи.
7. Открыть `/wp-admin/` без авторизации. Пользователь должен попасть на форму входа; восстановление пароля должно оставаться доступным через штатный экран WordPress.
8. Проверить форму на телефоне: поля, кнопка и сообщения должны помещаться без горизонтальной прокрутки.

## Ожидаемый результат

Авторизация использует существующие учётные записи WordPress. Новый модуль не хранит пароли и не создаёт отдельную базу пользователей. После входа состав меню и доступ к данным определяются действующими правами роли Horse Club OS.
